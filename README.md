# 格间小游戏

纯静态小游戏合集：数织、数独、扫雷、2048、数回（Slitherlink）、数桥（Hashiwokakero）、反应测试、瞄准训练。无需构建或服务器运行时，可部署到 GitHub Pages。

## 本地开发与测试

```sh
npm run dev
npm test
```

开发地址为 `http://localhost:7100`。测试使用 Node.js 内置测试工具，覆盖移动合并、失败判定、生成题目的解、单环和桥梁连通性。

新游戏的浏览器回归脚本为 `tests/training.browser.cjs`。启动本地服务后，在已安装 Playwright 和 Chromium 的环境运行 `node tests/training.browser.cjs`；可通过 `PLAYWRIGHT_MODULE` 指定已有 Playwright 模块路径。

## 游戏选择

顶部显示当前游戏，点击「切换游戏」打开游戏库。支持中文名、英文名、拼音搜索，以及分类筛选和最近三款游戏记录；游戏列表可独立滚动。手机为单列卡片，桌面为双列。

## 新增游戏

- **2048**：4 × 4 经典模式，方向键 / WASD / 屏幕按钮 / 滑动操作。合成 2048 后通关，排行榜比较合成用时；棋盘显示合并得分。
- **数回**：5 × 5、7 × 7，点击画线、右键或排除模式标记，支持撤销和清空。检查数字约束、顶点度数与单一闭环。
- **数桥**：7 × 7、9 × 9，点击岛屿间虚线循环单桥、双桥和删除。禁止交叉，检查岛屿桥数与全局连通。

- **反应测试**：随机等待变绿后点击，测量 5 次平均毫秒数，抢跑重试；支持鼠标、触屏、空格和 Enter。
- **瞄准训练**：30 秒点球挑战，大／中／小三种目标，统计命中数、准确率和平均命中耗时。

两款反应训练在打开菜单、窗口失焦或切换标签页时中断当前轮，避免无效计时。本机最佳成绩仍会保存；完整结束后可登录上传成绩。反应测试按 5 次平均毫秒数从小到大排序；瞄准训练按命中数从大到小排序，同命中数时按射击次数从少到多（准确率优先）排序。各球体大小独立排行。

数回和数桥从合法解生成题目，保证有解，但未做唯一解筛选；检查器接受所有符合规则的解。

## 动画反馈

所有游戏提供短时操作反馈：2048 方块滑动与合并、数织填色、数独输入、扫雷展开波纹，以及数回／数桥线条绘制和回收。重开或切换游戏会取消未完成的动画；系统开启「减少动态效果」时会自动关闭运动效果。

## GitHub Pages

现有 `.github/workflows/pages.yml` 会在推送到 `main` / `master` 时发布 `dist/`。仓库 Settings → Pages 的来源应为 GitHub Actions。所有资源使用相对路径，支持仓库子路径部署。

游戏本体无需 Firebase 即可运行。登录与排行榜沿用已有 Firebase 项目，新游戏排行榜需要另行发布仓库中的 `firestore.rules`（Pages 工作流不会发布 Firebase 规则）。新增规格使用独立编码，继续兼容现有查询、索引和旧成绩。

规则已通过 Firebase 云端编译检查及 41 项本地模拟器测试。排行榜为客户端上报成绩，不具备服务端防作弊验证。规则和新增索引需通过 `firebase deploy --only firestore:rules,firestore:indexes` 单独发布，GitHub Pages 只负责前端。

## 成绩上传回归

- `npm test`：检查各游戏排序、格式、毫秒精度与成绩字段校验。
- `node tests/scores.browser.cjs`：在 Playwright 环境运行真实页面配合内存 Firebase SDK，覆盖登录后上传、重复提交、失败重试、重新打开成绩，以及旧请求不覆盖新一局。不会写入线上成绩。
- `firebase emulators:exec --only firestore --project demo-gejian-score-tests --config firebase.test.json "python3 tests/firestore_rules.py"`：本地验证八款游戏成绩权限、必填字段、类型、范围、身份、重放和查询限额。

训练排行榜规格使用独立编码：反应测试 305、瞄准训练 330。新增 `averageMs`（两款训练）及 `hits` / `shots`（仅瞄准）字段按游戏校验，旧游戏数据和排名保持兼容。
