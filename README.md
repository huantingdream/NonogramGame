# 格间小游戏

React 19 + Vite 8 前端、Fastify 5 / Node.js 24 后端、MySQL 8.4 数据库。正式站点：**https://games.huantingdream.site**。Nginx 提供 HTTPS，Node.js 同时提供静态资源与 `/api`；运行期间不访问 Firebase、Google SDK 或外部字体服务。

13 款游戏的算法、Canvas 渲染和输入计时继续复用经过测试的游戏引擎。React 管理应用布局、游戏选择、账号、个人战绩和排行榜；`useGameRuntime` 管理引擎生命周期。棋盘以及共享结果 / 每日挑战控制器通过稳定容器接入，避免 React 重绘破坏画布、焦点和精确计时。

## 项目结构

- `src/components/`：React 界面；`src/hooks/`：引擎生命周期。
- `src/games/`：13 款游戏及注册表；`src/core/`：计时、音效、动效、每日挑战、成绩和 HTTP API。
- `shared/`：前后端共用成绩规则、格式与校验。
- `server/`：账号、会话、排行榜 API、数据库连接及版本化 SQL 迁移。
- `public/`：图标、攻略和首屏主题脚本；`dist/` 是构建产物，不提交 Git。
- `deploy/`：Nginx 与数据库备份脚本；`compose.yaml`：独立部署。

## 本地开发

需要 Node.js 24+、MySQL 8.4。创建本地数据库和专用用户后，将 `.env.example` 复制为 `.env`，填写自己的连接配置。生产密码仅存放在服务器。

```sh
npm ci
npm run db:migrate
npm run dev:server   # 终端一：Node.js API，127.0.0.1:3100
npm run dev          # 终端二：React，http://localhost:7100
```

Vite 将 `/api` 代理给 Node.js。访问地址应与 `.env` 中 `APP_ORIGIN` 完全一致。

```sh
npm run build
npm start           # 构建后的独立 Node.js 服务
npm test
npm run test:browser # 先启动 Vite；首次使用 npx playwright install chromium
```

MySQL 集成回归必须使用隔离库 `gejian_test`，在对应环境变量下运行 `npm run test:api`。脚本拒绝在正式库运行。GitHub Actions 自动执行单元、MySQL 集成、构建和浏览器测试，不再发布 Pages。

## 线上部署与运维

服务器目录 `/opt/gejian`，Compose 项目名 `gejian`，与现有机器人服务隔离。

- `app`：Node.js 24，非 root、只读容器，宿主仅监听 `127.0.0.1:3100`。
- `db`：MySQL 8.4，仅 Compose 内网可达，没有映射公网或宿主 3306 端口。
- 数据落盘到 `/opt/gejian/data/mysql`；密码在 `/opt/gejian/.env`，权限 0600。
- 历史密码参数位于 `/opt/gejian/private/hash-config.json`，只读挂载；备份不得置于 `public/` 或提交 Git。
- Nginx 配置 `/etc/nginx/sites-available/gejian`，证书由 Certbot 管理。Cloudflare 真实 IP 白名单仅应用于这个站点，避免所有访问者共用限流额度。

更新源码前备份，随后构建和启动：

```sh
cd /opt/gejian
sudo bash deploy/backup.sh
sudo docker compose build app
sudo docker compose up -d app
sudo docker compose ps
curl --fail http://127.0.0.1:3100/api/health
```

启动会执行尚未应用的 SQL 迁移。单机更新期间可能有几秒中断；后续不兼容数据库变更需要先制定回滚方案。不要执行 `docker compose down -v` 或删除 `data/`。

手动备份：`sudo bash /opt/gejian/deploy/backup.sh`，结果写入 `backups/gejian-时间.sql.gz`，仅服务器管理员可读。恢复到**空的隔离数据库**验证后，再计划正式恢复；不要直接覆盖正在使用的正式库。账号密码参数与 `.env` 也必须通过受控方式保留。建议额外配置异机备份。

## 账号与成绩迁移

2026-10-27 从旧 Firebase 项目迁入账号和排行榜，迁入 17 个账号、110 条成绩，保留 UID、昵称、成绩、题目种子及时间；无 `game` 的历史记录归为数织。导入在事务中执行并逐条校验，可重复执行而不覆盖新密码或成绩。

历史导出包含同一邮箱的两个不同 UID。两者分别保留，优先验证最近活跃账号，必要时匹配另一原密码；成绩不合并。新注册邮箱唯一。旧密码首次成功登录后自动升级为本站 scrypt 摘要，随后不再使用该账号的旧哈希。

- `scripts/export-firebase.cjs`：一次性管理员导出，需要显式授权及本机已有 Firebase CLI 登录；仅导出到受限私有目录，不输出令牌或密码材料。
- `scripts/retire-firebase.cjs`：经明确授权后停用旧服务，先保存恢复配置，保留全部旧数据。
- `scripts/import-firebase.mjs`：服务端事务导入；需数据库环境变量和 `IMPORT_DIR`。
- 旧 Firebase 数据保留作迁移回溯；经明确授权，旧邮箱认证和 Firestore 客户端访问已停用，恢复配置保存在服务器私有目录。前端和后端正常运行均不连接 Firebase。
- GitHub Pages 旧域名和新域名的浏览器本地存储互不共享。旧域名本机战绩、主题、每日打卡不会自动跨域迁移。当前站点登录后的个人战绩保存在 MySQL；当前浏览器已有本机战绩可从「战绩」导入。

账号会话使用随机 HttpOnly / Secure / SameSite Cookie，数据库只保存会话令牌哈希。写 API 校验来源和自定义请求头，登录限流，SQL 使用参数绑定。昵称和用户 ID 由服务端确定，成绩提交通过数据库唯一约束防止并发重复。

排行榜仍是客户端上报：服务端验证类型、范围、游戏规格与身份，但没有重放整局进行防作弊验证。目前没有邮箱验证、找回密码或社交登录功能，与旧站的邮箱密码登录范围一致。

## 游戏选择

顶部显示当前游戏，点击「切换游戏」打开游戏库。支持中文名、英文名、拼音搜索，以及分类筛选和最近三款游戏记录；游戏列表可独立滚动。手机为单列卡片，桌面为双列。

## 新增游戏

- **2048**：4 × 4 经典模式，方向键 / WASD / 屏幕按钮 / 滑动操作。合成 2048 后通关，排行榜比较合成用时；棋盘显示合并得分。
- **数回**：5 × 5、7 × 7，点击画线、右键或排除模式标记，支持撤销和清空。检查数字约束、顶点度数与单一闭环。
- **数桥**：7 × 7、9 × 9，点击岛屿间虚线循环单桥、双桥和删除。禁止交叉，检查岛屿桥数与全局连通。
- **管道**：5 × 5、7 × 7，点击格子顺时针旋转 90°。题目由随机生成树保证有解，所有管口两两对接且全网连通时自动通关。
- **点灯**：7 × 7、10 × 10，点击白格放灯，右键或标记模式打 · 备忘。灯不互照、数字黑格恰好满足、全棋盘照亮时自动通关；冲突灯会红色高亮。
- **数墙**：7 × 7、10 × 10，点击格子在 未定 → 海 → 岛 间切换。海连通、无 2×2 海块、每座岛恰含一个数字且大小相等时自动通关。生成时从单点生长海并避开 2×2，天然保证合法。
- **聪明格**：4 × 4、6 × 6，选中格子后用数字键盘或键盘输入。每行每列 1–N 不重复，每个粗线笼满足左上角算式。题目由随机拉丁方切笼生成。
- **合成大西瓜**：Canvas 圆形刚体物理（自研，无依赖），移动瞄准后点击 / 空格丢下水果，同级相碰沿 11 级合成链升到西瓜，双西瓜相撞湮灭加分。水果堆持续越过警戒线即结束，排行榜按得分排序。

- **反应测试**：随机等待变绿后点击，测量 5 次平均毫秒数，抢跑重试；支持鼠标、触屏、空格和 Enter。
- **瞄准训练**：30 秒点球挑战，大／中／小三种目标，统计命中数、准确率和平均命中耗时。

两款反应训练在打开菜单、窗口失焦或切换标签页时中断当前轮，避免无效计时。本机最佳成绩仍会保存；完整结束后可登录上传成绩。反应测试按 5 次平均毫秒数从小到大排序；瞄准训练按命中数从大到小排序，同命中数时按射击次数从少到多（准确率优先）排序。各球体大小独立排行。

### 反应计时的精度边界

- 起点：在 `requestAnimationFrame` 中仅更新变色提示，然后读取 `performance.now()`；不在关键帧重建成绩栏，也不使用 rAF 回调参数作为变色时刻。
- 终点：鼠标 / 触屏 `pointerdown`、键盘 `keydown` 的 `event.timeStamp`，在聚焦和界面更新之前读取。它与起点归一到相同时间基准，不把处理函数排队延迟算进成绩；无效时间戳直接作废，变色前产生但变色后送达的输入仍判为抢跑。
- 变色后的下一帧仅检查异常卡顿：超过 50 ms 则本轮不计成绩。它不会重设计时起点；该阈值是保守的质量检查，不是硬件延迟补偿，也不能检测所有渲染延迟。
- 等待与测量期间临时暂停背景渲染、取消测试区域残留动画，且停止共享计时器的跳秒更新；结束、中断、重置或切换游戏后释放暂停，不修改背景偏好。
- 保留每轮原始小数精度，平均后才取整。`npm test` 包含事件排队、延迟送达的抢跑、变色帧卡顿、五轮结算和取消清理的确定性回归。

网页只能估计提交变色的时间，不能直接获知屏幕像素发光或实体按键触发的时刻。刷新率、显示器扫描与响应、输入设备延迟、浏览器时间戳精度仍会影响成绩；不做固定减去一帧或几毫秒的“校准”。上述自动化测试验证软件逻辑，不代表经过外部硬件测量的端到端精度。

数回和数桥从合法解生成题目，保证有解，但未做唯一解筛选；检查器接受所有符合规则的解。管道、点灯、数墙、聪明格同样保证有解并接受任意合法解。

## 每日挑战与打卡

顶栏「每日挑战」按 日期 + 游戏 + 规格 推出确定性种子，所有玩家当天同题。完成任意一款即打卡，连续天数保存在本机；每日挑战使用固定规格（如数织 10×10 普通、扫雷中级）。

进入每日挑战会先等待目标游戏挂载完成，再套用规格和种子；被后续切换取代的请求不会重开旧游戏。聪明格每次重开都会按当前棋盘规格同步数字键盘。

## 战绩与分享

登录后每局结算自动保存到 MySQL 的 `personal_plays`，顶栏「战绩」按当前账号查看总对局、完成次数、累计用时、各游戏最佳和最近 20 条记录。服务器保留全部个人记录，汇总不受 300 条限制；另一个设备登录同一账号即可看到相同战绩。

未登录时仍保留最近 300 条本机战绩。登录后在「战绩」点击「将本机 N 条战绩导入此账号」，显式归入当前账号；导入保留原始时间，按每条记录 ID 去重。导入后这批记录不会再作为访客记录出现。未知或损坏记录保留在本机并提示，不会悄悄丢弃。

断网时已登录账号的记录进入按 UID 隔离的本机待同步队列，恢复网络、切回页面、打开战绩或点击刷新时重试；有待同步记录时每 30 秒重试。服务端同时校验登录会话与队列账号，避免跨标签页切换账号导致串号。已成功保存的记录无需再依赖浏览器存储；尚未同步的记录仍需保留本机数据。

`GET /api/me/stats` 只读取当前用户汇总；`POST /api/me/plays` 每批最多 20 条、事务写入、重复记录不覆盖原值。公开排行榜仍需手动提交，两者互不影响。扫雷失败也记录个人战绩；2048 和合成大西瓜按已结算分数统计个人最佳。

通关弹窗可保存分享卡片（Canvas PNG）或复制战绩文案。每日挑战打卡和游戏面板中标注「本机最佳」的即时提示仍是独立的本机功能。

## 主题与音效

顶栏可手动切换深色 / 浅色（未手动选择时跟随系统，选择持久化）；音效为 WebAudio 合成的短音，可随时开关。系统开启「减少动态效果」时自动关闭运动效果。

顶栏也可单独暂停动态玻璃背景，设置保存在当前浏览器。若用户尚未选择，反应测试会默认暂停背景动效以减少视觉干扰，离开后恢复其他游戏的动态背景。

## 攻略页

`public/guide/` 提供全部 13 款游戏的静态攻略页（规则 + 技巧），由 `node scripts/build-guides.mjs` 生成，利于搜索引擎收录；游戏内「怎么玩」弹窗有对应链接。

## 动画反馈

所有游戏提供短时操作反馈：2048 方块滑动与合并、数织填色、数独输入、扫雷展开波纹，以及数回／数桥线条绘制和回收。重开或切换游戏会取消未完成的动画。

管道、点灯、数墙、聪明格使用保留格子节点的更新方式，颜色过渡和键盘焦点不会随操作丢失。管道有 90° 旋转及接通高亮；点灯沿新照亮的格子扩散暖色光晕；数墙岛屿完成、聪明格算式满足时有短暂提示，新增冲突轻微抖动。共享棋盘边框与半透明计分卡适配深浅主题，系统开启「减少动态效果」时关闭这些动效。
